# Закрытый маршрут Telegram

Маршрут нужен, если основной сервер не может связаться с Telegram, а второй может.
Скопируйте оба шаблона SSH и подставьте адреса своей установки. `__PRIMARY_IPV4__` — основной сервер, `__PEER_IPV4__` — второй сервер, `__DOCKER_GATEWAY_IPV4__` — шлюз сети Docker, в которой работает Kuma. В примерах можно обозначить серверы как `192.0.2.10` и `198.51.100.20`.

На основном хосте отдельный пользователь запускает штатный OpenSSH.
Служба слушает только частный шлюз Docker на порту 19080; публичный порт
не открывается. На втором хосте отдельная учётная запись допускает только
пересылку TCP к `api.telegram.org:443`. Для неё запрещены сеансы, команды,
обратные и файловые пересылки, пароль и передача доступа к ключам.
Остальные правила входа проверяются до и после изменения; SSH перечитывает
только проверенную настройку, существующие подключения сохраняются.

Вход к порту 19080 разрешён отдельным правилом UFW только на собственном
мосту Docker, из подсети Kuma к адресу её шлюза. Внешний интерфейс в правило
не включён. При смене частной сети оператор сначала проверяет новый шлюз;
общий доступ к прокси не включается.

Создаётся новый отдельный ключ. Личные ключи владельца не копируются.
Ключ доступен только пользователю службы на основном хосте и не монтируется
в Kuma. Ключ узла назначения берётся из уже проверенного соединения и
закрепляется в `known_hosts`. Проверка сертификата Telegram остаётся включённой.
Служба ограничена 5% процессора, 64 МБ памяти, 16 задачами и 256 дескрипторами.
При обрыве она повторно подключается с паузой 15 секунд.

В `pilot.json` оператор задаёт `notificationProxy` равным
`socks5h://__DOCKER_GATEWAY_IPV4__:19080`, подставив адрес своего шлюза. Контроллер передаёт это значение через
`KUMA_NOTIFICATION_PROXY`; без настройки оно пустое. Оно используется
штатным механизмом `NOTIFICATION_PROXY` для HTTP-каналов оповещений.
Подготовленные SMTP-каналы, проверки сайтов и индивидуальный ИИ этот маршрут
не используют. Другие HTTP-провайдеры этой установки потребуют отдельного
решения, потому что назначение маршрута ограничено Telegram.

Перед включением проверяются: фактический шлюз своей сети, владельцы файлов,
применение правил к новой учётной записи, неизменность входа прежних пользователей,
запрет команд и иных адресов, официальный ответ Telegram через маршрут.
Пересоздаётся только свой сервис Kuma; остальные приложения не выбираются.
Неопределённая прежняя отправка не повторяется и не объявляется доставленной.
Новая проба имеет отдельную запись; получение подтверждает владелец.

Сохраняются прежние настройки, новый ключ и точка возврата в закрытых бессрочных
копиях. Отключение маршрута: убрать `notificationProxy`, пересоздать только свой
Kuma, затем остановить только `uptime-kuma-telegram-tunnel.service`.
Удаление пользователей и ключей не является частью смены версии.

Правила пересылки и запрета сеансов основаны на
[sshd_config](https://man.openbsd.org/sshd_config) и
[ssh](https://man.openbsd.org/ssh).
