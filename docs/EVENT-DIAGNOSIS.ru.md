# Диагностика по событию и дополнительные наблюдения

Администратор проекта отдельно подтверждает текущим паролем согласие на
будущую передачу наблюдений ИИ. По умолчанию режим выключен. Настройка не
меняет подключение ИИ и не выполняет пробный платный запрос. Нужна ранее
проверенная собственная подписка или API. Поля, разрешённые к передаче,
остаются теми же, что при ручном анализе. Секреты и содержимое ответа сайта
не передаются.

Два свежих подряд сбоя одной непрерывной серии позволяют создать один запрос.
Повтор подавляется в базе в той же операции, что и создание задания. Запуск
после перезагрузки не повторяет неопределённый запрос. Новое событие возможно
после двух свежих непрерывных успешных проверок. Пауза, обслуживание, отсутствие
данных и смена серии наблюдений не подтверждают новый сбой или восстановление.

Действуют отдельный предел 1–50 автоматических запросов в день, общий предел
ИИ проекта, одна очередь на проект и общий предел очереди. Отменённые и
неопределённые запросы учитываются в расходе. Фактическая денежная стоимость
может быть неизвестна. При изменении настроек ИИ, состава прав или связей
проекта нужно новое согласие. Отключение отменяет ожидающий анализ и
прерывает уже выполняющийся запрос без обещания возврата расхода.
Автоматика обрабатывает проекты до 200 проверок; превышение показано в форме,
частичная обработка такого проекта не выдаётся за полную. Проекты обходятся
порциями без постоянного исключения последующих проектов.

Разрешение анализа не разрешает изменение файлов. Для исправления владелец
отдельно просматривает конкретный план и подтверждает его текущим паролем.
До изменения сохраняется зашифрованная копия, затем проверяется результат.
Действует закрытый сценарий возврата заранее утверждённого JSON-файла:
произвольные команды, файлы и новые значения от ИИ не выполняются.
Полное автоматическое изменение без подтверждения каждой операции в этот
этап не входит. Подключение исполняемых правил для рабочих приложений требует
точного файла, проверенного образца и доступа, выделенного владельцем.

Связи проверок задаются внутри проекта. Нельзя указать чужую проверку,
саму себя или создать круговую цепочку; максимум пять прямых зависимостей.
Связи показывают возможную общую причину, не переписывают состояние сервиса
и не отключают оповещения.

Рост задержки рассчитывается по 15 подряд успешным измерениям без разрывов:
срединное значение последних пяти сравнивается с предыдущими десятью.
Отметка появляется при росте не меньше 50% и 100 мс. Это подсказка,
а не новый критерий отказа. Для отказа по времени ответа задаётся отдельный
предел в проверке скорости. Пропуски и ошибки без измерения не превращаются
в нулевые значения или непрерывную линию графика.

Подписка использует официальный [вход и режим вывода для открытых приложений](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference):
ответ успешен только после `response.completed`, хранение у провайдера
отключено, прерванный вывод учитывается отдельно. Для API используется
[строгий формат результата](https://developers.openai.com/api/docs/guides/structured-outputs).
Подключение локальной копии не переносится на другую установку без отдельного
официального входа владельца.
