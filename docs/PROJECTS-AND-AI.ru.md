# Проекты, доступ и индивидуальный ИИ

Третий этап ТЗ, независимый форк `ub3dqy/uptime-kuma`.
Подтверждаемое исполнение четвёртого этапа описано отдельно:
[исправление сбоев](APPROVED-RECOVERY.ru.md).
Рабочая установка и бессрочное хранение её копий этим этапом не меняются.

## Как пользоваться

1. Откройте **Проекты**, создайте проект и задайте название и часовой пояс.
   Прежние проверки остаются в личном пространстве вместе с историей.
2. Добавьте проверки, настройте проектные оповещения и пригласите участников.
   Ссылку администратор передаёт сам; приложение никому её не рассылает.
3. В **Персональный ИИ** выберите API или собственную подписку ChatGPT.
   Сохраните настройки, получите доступные модели, выберите модель и выполните
   отдельный пробный запрос. Только полный ответ подтверждает подключение.
4. Для объяснения сбоя сначала просмотрите точные данные, затем нажмите
   **Отправить на анализ**. Ответ разделяет факты, предположения, уверенность,
   следующие шаги и ограничения. ИИ не выполняет команды и ничего не исправляет
   самостоятельно. Исполнение разрешённых действий относится к четвёртому этапу.

| Роль                  | Что доступно                                                                          |
| --------------------- | ------------------------------------------------------------------------------------- |
| Наблюдатель           | Проверки, карточки, сводки, состояние оповещений и готовые объяснения                 |
| Оператор              | Дополнительно создание и изменение новых проектных проверок, пауза, запрос объяснения |
| Администратор проекта | Дополнительно участники, роли, каналы, получатели, тесты оповещений, ИИ и журнал      |

Участник выбирает свой пароль при принятии приглашения. Ссылка действует
24 часа, используется один раз и может быть отозвана. Последнего администратора
удалить нельзя. Пароль и вход с дополнительным кодом доступны через меню
учётной записи. Включение дополнительного кода требует его проверки на сервере.

Прежние владельцы сохраняют права **администратора установки**, включая общие
настройки. Роль наблюдателя в проекте не отменяет их прежних общих полномочий.
Для доступа только к проекту приглашайте отдельную новую учётную запись.
Интерфейс участников показывает это различие.

Клиентские группы отчётов не превращаются в проекты и не дают прав доступа.
Удаление участника не удаляет проверки или историю. После отзыва прав открытая
страница очищается при следующем обновлении (обычно до пяти секунд);
новые серверные запросы сразу отклоняются.

## Проверки и оповещения

Новые проекты поддерживают HTTP/HTTPS, поиск текста, простое поле JSON, DNS A,
TCP и входящий отчёт процесса копирования. JSON принимает путь вида
`services[0].state`, без функций и вычисляемых выражений. Входящий отчёт
не создаёт и не проверяет резервную копию: это обязанность внешнего процесса.

Доступны публичные IPv4-адреса. Точные внутренние IPv4-адреса при создании
проекта или в его настройках может разрешить администратор установки. Остальные внутренние,
служебные, зарезервированные и IPv6-адреса блокируются, в том числе для
проектного SMTP. Разрешение адреса не открывает всю подсеть. Подмена DNS
и переадресация не обходят проверку: соединение использует проверенный адрес.
Проверка TLS остаётся включённой. HTTP-ответ ограничен 1 МиБ, время ограничено.

Прежние сложные проверки редактируются через исходный интерфейс владельца.
Их история и возможности не урезаются. Приглашённый участник не получает
доступ к исходным общим настройкам.

Проектные SMTP и Telegram используют прежнюю очередь: отдельный тест,
различие отправки и получения, отмена старых редакций, ограниченные повторы
при определённом отказе. Закрытые настройки новых проектных каналов
зашифрованы целиком. Операторы и наблюдатели не получают адреса получателей,
имена входа, пароли и токены. Ранее созданные каналы пошаговой настройки
личного рабочего пространства шифруются при следующем входе первоначального
владельца. Классические формы сохраняют прежний порядок работы; их настройки
шифруются при следующем сохранении. Сохранённые пароли пошаговых каналов
повторно не возвращаются в браузер.

## OpenAI API

Администратор вводит собственный ключ в закрытое поле. После сохранения ключ
не возвращается в браузер. Список моделей запрашивается отдельно от анализа;
нет заранее выбранной платной модели или автоматического пробного запроса.
Выполнение начинается только по кнопке проверки или анализа.

Используются официальный Responses API, `store: false`, потоковый ответ
и строгая структура результата. Инструменты, файловый доступ и команды
не подключены. Успех фиксируется только после `response.completed`;
неполный или отказной ответ не превращается в диагноз.

## Собственная подписка ChatGPT

Использован официальный механизм для открытых приложений:

- [Общий порядок входа](https://developers.openai.com/siwc/quickstart).
- [Регистрация приложения и вход](https://developers.openai.com/siwc/token-sharing-open-source/sign-in).
- [Учётные записи, обновление и отзыв](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions).
- [Модели и запросы](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference).
- [Вход для собственного сервера](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms).
- [Ограничения предварительной версии](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

При первом входе Uptime Kuma запрашивает собственную регистрацию
`dynamic_agent_client`. Выданный настоящий `client_id` сохраняется для проекта;
`dynamic_agent_client` не используется при обмене кода. Обратный переход —
точный `http://127.0.0.1:<порт>/auth/callback`. Применены свежие state, nonce,
PKCE S256 и проверка подписи, издателя, получателя, срока, nonce, личности
и нужных разрешений токена.

На одном компьютере с сервером кнопка открывает официальный вход. Это доступно
только с `UPTIME_KUMA_LOCAL_OAUTH=1` при привязке сервера к `127.0.0.1`.
Для удалённого сервера администратор скачивает помощник и одноразовый файл
сопряжения, запускает их на компьютере с браузером:

```text
node uptime-kuma-ai-sign-in.cjs uptime-kuma-pairing.json
```

Нужен Node.js с поддержкой встроенного fetch. Помощнику не нужны файлы проекта
или установленные пакеты. Он получает разрешённый вход и передаёт его только
на точный HTTPS-адрес этой установки. Файл сопряжения действует десять минут,
связан с администратором, проектом и редакцией настроек, используется один раз.
Он не содержит прежних ключей, но даёт право завершить подключение:
храните его закрыто и не передавайте третьим лицам.

У каждого проекта свой постоянный непрозрачный `ext_agent_host_id`.
Помощник использует значение сервера. Чужие приложения, их `auth.json`,
сеансы и клиентские идентификаторы не читаются. Для другого аккаунта есть
явный переключатель; повторный вход обычно подтверждает прежнюю личность.
Одновременно в проекте активна одна учётная запись ИИ.

Страница обратного перехода работает, пока открытый запрос входа действителен
(десять минут). Если браузер сообщает об отказе подключения к локальному адресу,
запустите новый вход из настроек проекта. Старый адрес повторно не используйте.

Список моделей и доступность зависят от аккаунта и разрешений.
Каталог ограничен 2 МиБ, поток ответа — 512 КиБ. Принимается только завершённый
ответ с проверенной структурой; частичные фрагменты и промежуточные рассуждения
не показываются как результат.
Обновление входа использует собственный refresh token, учитывает разрешённое
время обновления и сохраняет его замену. При отключении выполняется официальный
отзыв. Если провайдер не подтвердил отзыв, местный доступ удаляется,
но интерфейс прямо сообщает о необходимости проверить разрешение в ChatGPT.
Подписка не подменяется API. Поле `max_output_tokens` для подписки официально
не поддерживается и не отправляется. Лимиты плана и кредитов управляются в ChatGPT.

Приёмка 2 ноября 2026 года: владелец выполнил официальный вход в локальной
копии, затем настоящий пробный запрос к `gpt-6.1-sol` завершился полным ответом.
Последний успешный запрос: 242 входных и 170 выходных токенов. До него сохранены
три неудачные проверки совместимости; они не переписаны как успешные и могли
израсходовать доступный объём подписки. Денежная стоимость неизвестна.
Сведения о рабочих сайтах в этих пробах не передавались, API не подставлялся.

На этом компьютере защитная программа проверяет HTTPS своим сертификатом.
Локальный сервер запускается на Node 24 с `node --use-system-ca ...`, чтобы
использовать уже доверенные сертификаты Windows. Проверка TLS не отключается;
импорт нового корневого сертификата и изменение защитной программы не требуются.
В другой среде этот параметр выбирают по её настройкам доверия.

## Данные, ограничения и очередь

### Автоматическая диагностика выбранных проверок

В разделе персонального ИИ администратор выбирает конкретные проверки,
включает автоматическую диагностику и подтверждает передачу будущих данных
текущим паролем. Учебные примеры и неактивные проекты можно исключить.
Новые проверки не добавляются к разрешённому набору автоматически.
Выбор чужих проверок и групп отклоняется сервером.

Анализ начинается после двух свежих последовательных неудачных наблюдений.
Пропуски, пауза, обслуживание и старые данные не запускают ИИ. Один и тот же
непрерывный сбой разбирается один раз, включая перезапуски. Новая попытка
возможна после двух свежих успешных наблюдений и нового сбоя. Отмена или
неизвестный исход не означают разрешение повторно расходовать подписку.

Действуют отдельный дневной предел автоматических разборов и общий предел
проекта. Смена прав, настроек ИИ или состава разрешённых проверок отменяет
устаревшие ожидающие задания. Причина передаётся структурированно, например
«страница не найдена, HTTP 404»; необработанные сообщения и ответы страниц
не отправляются. Названия и адреса по-прежнему зависят от настроек приватности.

Заключение ИИ само ничего не меняет. Для исправления нужны отдельный
проверяемый план, подтверждение владельца, сохранённая точка возврата
и новые наблюдения после применения. Наличие сбоя не разрешает менять
рабочие сайты или критерии успешной проверки.

По умолчанию передаются состояние, тип, категория ошибки, время, задержка
и несколько сохранённых наблюдений. Названия и имена узлов администратор
включает отдельно. Полные URL, подписи, пароли, ответы страниц и необработанные
журналы не отправляются. Перед анализом показан точный набор;
изменение наблюдений требует нового просмотра.
У успешной проверки нет причины недоступности. Пауза родительской группы
учитывается так же, как в карточке сбоя. Ссылки в проектных оповещениях
открывают конкретную проверку в соответствующем проекте.

В базе сохраняются отдельные задания каждого проекта. В проекте допускается
одно незавершённое задание; всего одновременно выполняется не более двух,
очередь ограничена сотней. Действуют предел запросов за день проекта,
время ожидания и отдельный предел API-ответа. Отменённые запросы тоже считаются
в дневном пределе: это консервативное ограничение, а не счёт оплаченных запросов.

После отмены, смены прав или настроек старый результат не выдаётся.
После прерывания начатый запрос автоматически не повторяется.
Неизвестный исход обозначается явно: провайдер мог уже учесть расход.
Если денежная стоимость не возвращена, она неизвестна. Предел запросов
не обещает жёсткого денежного лимита.

Пробное оповещение также привязано к вызвавшему его администратору: отзыв прав
до отправки отменяет ожидающий тест. Автоматические сообщения о сбоях используют
сохранённый канал проекта и не зависят от того, кто первоначально его настроил.

## Хранение ключей и восстановление

Ключи ИИ и новые настройки каналов защищены AES-256-GCM, связаны с проектом
и назначением; канал также связан с владельцем данных. Перенос зашифрованной
записи в другой проект или к другому владельцу не открывает её.

Главный ключ находится вне SQLite, по умолчанию
`<data-dir>/project-secrets/keys.json`. Можно задать отдельный защищённый файл
через `UPTIME_KUMA_PROJECT_KEY_FILE`. Нужна выделенная закрытая папка:
на Unix каталог 0700 и файл 0600; на Windows доступ текущему служебному
пользователю, SYSTEM и при необходимости администраторам.
Общедоступная папка, небезопасный файл и символические ссылки не принимаются.

**Копия только базы недостаточна.** Защищённый комплект должен включать
согласованную копию базы, необходимые файлы данных, все версии ключей,
конфигурацию и точную версию приложения. Храните его зашифрованным
с отдельным контролем доступа. Бессрочное хранение копий сохраняется.

Смена ключа доступна только администратору установки с повторным паролем
через закрытую операцию `projectRotateKey`. Действующие записи перешифровываются,
старые версии ключа сохраняются для старых копий. Настройки ИИ требуют новой
проверки. Ключи нельзя удалять, пока должны читаться связанные копии.
Потерянный ключ не заменяется автоматически: восстановите защищённый комплект
или заново подключите аккаунт после отдельного решения владельца.

Приглашённые участники и технические владельцы данных не активируются в старой
таблице входа; пароли участников хранятся отдельно. Запуск прежней программы
не превращает их в администраторов установки. После появления новых проектов
или участников удаление миграции отклоняется. Для отката нужен предшествующий
комплект, а не потеря новых данных. Два сервера не должны работать над одной базой.

## Приёмка и границы

Повторяемые проверки: `npm run build`, `npm run test-workspace` и серверные
проверки репозитория на поддерживаемом Node. Испытания создают новую закрытую
папку `private/e2e-workspace-*`, локальные HTTP/TLS/DNS/SMTP и учебный ИИ.
Помощник входа исполняется как скачанный отдельный файл. Настоящие аккаунты
и рабочие сайты в автоматических проверках не используются.

Результаты этапа — `outputs/stage3-20261101/REPORT.ru.txt`.
Настоящая подписка проверена с участием владельца отдельно от учебных испытаний.
Не заявляется приёмка внешнего почтового ящика, Telegram, реального API-ключа,
MariaDB, нескольких серверных процессов
или всего исторического набора модулей. Возможность подключения и подтверждённое
реальное подключение — разные результаты.
