# Управление Uptime Kuma из Telegram

Бот открывает русское меню одного выбранного проекта. `/start` показывает
сводку. Из меню можно найти монитор по названию, открыть карточку с последней
проверкой, посмотреть историю и отчёт за сутки, узнать сроки сохранённых
сертификатов и проверить журнал отправки уведомлений. Можно подключить
управление в тот же личный чат, куда Kuma отправляет уведомления.

Наблюдатель видит данные проекта. Оператор или администратор может поставить
монитор на паузу, возобновить его, открыть техработы на 15, 30, 60 или 120 минут и
закрыть начатое ботом окно раньше. Техработы используют штатное расписание Kuma
и заканчиваются автоматически, включая перезапуск приложения. Результат
отправки «Принято сервисом» означает, что сообщение принял поставщик. Фактическое
получение отмечается отдельно, когда его подтвердили в настройках канала.

Команды разрешены одному числовому Telegram ID в личном чате. Права выбранного
пользователя Kuma проверяются при каждом обращении и повторно при подтверждении
изменения. Подтверждение действует две минуты, применяется один раз и сбрасывается
при перезапуске. В меню «Журнал действий» видны последние изменения этого
пользователя из Telegram. Полные записи хранятся в журнале проекта.

## Диагностика ИИ

Откройте **Личный ИИ** в главном меню или введите `/ai`. Там видно состояние
подключения и последние запросы диагностики, включая запуски по событию.
Администратор также видит состояние автоматической диагностики.

1. Откройте карточку нужного монитора и нажмите **Диагностика ИИ**.
2. Нажмите **Посмотреть данные и запустить**. Бот покажет наблюдения, которые
   разрешено отправить ИИ в этом проекте. По кнопке **Отправить ИИ** запрос
   встаёт в общую очередь и учитывается в суточном лимите. Если наблюдения
   успели измениться, откройте предпросмотр заново.
3. Нажмите **Статус запроса**, затем **Обновить**. Когда ответ готов, бот
   показывает факты, возможные причины и следующие шаги. Длинный ответ целиком
   доступен по кнопке **Открыть ИИ в панели**. Свой ожидающий или выполняющийся
   ручной запрос можно отменить. Уже отправленный запрос мог использовать лимит.

Наблюдатель видит историю диагностики. Оператор и администратор могут запускать
анализ через уже подключённый ИИ. Подключение, разрешения на передачу данных,
автоматическую диагностику и планы исправлений настраивают в панели Kuma.

## Подключение действующего бота

1. Выберите включённый канал Telegram в разделе «Уведомления» нужного проекта.
   Данные этого канала должны быть сохранены в защищённом хранилище проекта.
   Получателем должен быть ваш личный чат с ботом. Для проверки оператор может
   посмотреть тип чата через [Telegram Bot API](https://core.telegram.org/bots/api#getchat).
2. В файле управления укажите ID выбранного канала Kuma в `notificationId`.
   В `botId` укажите числовой ID бота из [ответа getMe](https://core.telegram.org/bots/api#getme).
   В `telegramUserId` укажите числовой ID вашего аккаунта, совпадающий с получателем
   личных уведомлений. В `userId` и `projectId` укажите пользователя и проект Kuma.
   Файл содержит только эти идентификаторы. Kuma берёт токен из сохранённого канала.

```json
{
  "version": 1,
  "notificationId": 1,
  "botId": 123456789,
  "telegramUserId": 987654321,
  "userId": 1,
  "projectId": 1
}
```

При смене получателя или отключении канала управление через него приостанавливается.
При замене самого бота обновите `botId` и перезапустите Kuma.

## Подключение отдельного бота

Для отдельного бота используйте `/newbot` в [BotFather](https://t.me/BotFather) и нажмите
«Старт» в личном чате. Числовой ID владельца можно сверить по полям `message.from.id`
и `message.chat.id` первого личного сообщения. Оба значения должны совпадать.
[Документация Telegram](https://core.telegram.org/bots/api#getupdates)

Укажите `token` в защищённом файле вместе с `version`, `telegramUserId`, `userId`
и `projectId`. Поля `notificationId` и `botId` относятся к подключению через
сохранённый канал.

## Порядок включения

1. На сервере создайте файл конфигурации. Для пилотной установки путь
   `/srv/uptime-kuma-pilot/data/telegram-control/config.json`. Владелец каталога и
   файла — пользователь Kuma (UID 1000 в пилоте), права каталога `0700` и файла
   `0600`.
2. Для пилота укажите `"telegramControl": true` в `pilot.json` и примените
   конфигурацию Compose после установки сборки. Для других установок укажите
   абсолютный путь к файлу в `UPTIME_KUMA_TELEGRAM_CONTROL_CONFIG` и перезапустите
   Kuma. При наличии `NOTIFICATION_PROXY` команды используют тот же закрытый маршрут
   к Telegram. Для приёма команд нужен один получатель обновлений и выключенный вебхук.
   [Документация Telegram](https://core.telegram.org/bots/api#getupdates)
3. Отправьте `/start` в личном чате и проверьте, что сводка относится к нужному
   проекту. На тестовом мониторе подтвердите паузу и возобновление. Откройте короткое
   окно техработ, проверьте его в панели и завершите из чата. Для проверки
   автоматического окончания дождитесь конца отдельного короткого окна.
4. При использовании действующего бота запросите тест отправки в разделе
   «Уведомления». Убедитесь, что команды и уведомление видны в одном личном чате.

Доступ можно снять сразу, отозвав роль выбранного пользователя Kuma в проекте.
Чтобы отключить весь бот в пилоте, уберите `telegramControl` из `pilot.json` и
примените конфигурацию Compose. В других установках уберите переменную
`UPTIME_KUMA_TELEGRAM_CONTROL_CONFIG` и перезапустите Kuma. Уже сохранённые окна
техработ продолжат действовать по своему расписанию и доступны в панели.
